# Dedala

Dedala is an iPhone app that your agent builds into your own assistant. The app
itself ships almost nothing: a conversation, a search and settings. Your agent,
a [Hermes Agent](https://hermes-agent.nousresearch.com) running on your own
machine, draws the rest: cards in the conversation, pages that become the app's
tabs, Live Activities, widgets. Two people with two agents end up with two
different apps.

Dedala is an independent project, not affiliated with Nous Research.

## What your agent can give you

- **Conversations** with your agent, with cards you can act on: a reply to
  approve, a choice to make, a timer to start.
- **Pages** it creates and keeps up to date: your day, your inbox, a project, a
  trip. They are the app's tabs, and Search finds everything in them.
- **Live Activities and widgets** it designs, on the lock screen and the home
  screen.
- **Sharing** from any app to your agent, and its notifications on your phone.

## Getting started

Dedala is in beta, by invitation.

1. **The app.** Install Dedala on your iPhone from the invitation you received.
2. **The plugin.** On the machine where your Hermes Agent runs (Linux for now):

   ```
   hermes plugins install dedala-app/dedala#plugin/dedala
   ```

   Hermes asks whether to install the plugin's Python dependencies; answer yes.
   Nothing is compiled on your machine: on first use, the plugin downloads its
   native code, one WebAssembly module, from this repository's releases.
3. **Pairing.** With the relay token from your invitation:

   ```
   hermes dedala pair --token-file <file holding the token>
   ```

   It prints a code. In the app, open Settings › Pair with your agent and scan
   it.

`hermes plugins update dedala` brings the plugin up to date.

## Privacy

What your agent knows stays on your machine. The phone and the agent reach each
other through Dedala's relay, which holds messages while one side is away and
sends the notifications, but cannot read any of them: everything is sealed
between your phone and your agent. The relay's code is in this repository.

## For agent developers

The app and the agent speak the protocol in [docs/protocol.md](docs/protocol.md).
Cards and pages are written in a JSON language the app draws as native views,
described in [docs/dedala-ui.md](docs/dedala-ui.md), with examples in
[docs/dedala-ui/examples](docs/dedala-ui/examples).

## Building and testing

The Xcode project is generated by XcodeGen from `project.yml`. The app is built
on a Mac with `./mac`, which can run from another machine over SSH: `MAC_HOST`
names the Mac (`user@host`), `MAC_DIR` the folder there (`dev/assistant-app`),
and `DEVICE` an iPhone's identifier; they can live in `.mac.env`, which git
ignores. `./mac help` lists its commands.

| Command | What it checks |
|---|---|
| `./mac test` | the app, in the simulator |
| `nix-shell relay/shell.nix --run "cd plugin && python -m pytest"` | the plugin, against a real relay |
| `nix-shell relay/shell.nix --run "cd relay && python -m pytest"` | the relay |
| `nix-shell relay/shell.nix --run "python -m pytest twin/tests"` | the layout checks |
| `cd native && nix shell nixpkgs#rustup -c cargo +stable test --features plugin` | the native code |
| `nix-shell relay/shell.nix --run "reuse lint"` | that every file states its licence |

The plugin's native code is one WebAssembly module, built from `native/` by
`nix-build native/wasm.nix`, which gives the same file on any machine. A
`native-*` release carries it; the plugin downloads it on first use and takes it
only if its hash is the one `plugin/dedala/native.py` names, so installing the
plugin compiles nothing. After a change in `native/`, put the new build's hash
and the next release's name there, then push that tag: CI builds the module,
checks the hash and publishes the release. The tests use the local build
(`DEDALA_WASM`, set by `relay/shell.nix`).
